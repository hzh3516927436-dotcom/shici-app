# 诗词数据规范（所有数据生成代理必须严格遵守）

## 总则
- 每个输出文件是一个纯 JSON 文件（UTF-8、无注释、无尾逗号、无 BOM），顶层结构固定为：
```json
{
  "poems": [ ... ],
  "poets": [ ... ]
}
```
- `poems` 是诗词数组，`poets` 是该文件涉及诗人的小传数组。

## poem 对象字段（全部字段名精确一致）

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 格式固定为 `组号-三位序号`，如 `G4-007`。组号见任务指派，序号从 001 连续递增 |
| `title` | 是 | 篇名。长诗节选时篇名后加`（节选）`，如 `琵琶行（节选）` |
| `author` | 是 | 作者姓名；佚名一律写 `无名氏`；《诗经》《乐府》篇目作者写 `无名氏` |
| `dynasty` | 是 | 只能取以下值之一：`先秦` `汉` `魏晋` `南北朝` `隋` `唐` `五代` `宋` `元` `明` `清` `近代` |
| `form` | 是 | 体裁，只能取以下值之一：`四言诗` `楚辞体` `乐府诗` `五言古诗` `七言古诗` `五言绝句` `七言绝句` `五言律诗` `七言律诗` `词` `散曲` |
| `tune` | 词、散曲必填，其他体裁不要此字段 | 词牌或曲牌名，如 `水调歌头` `天净沙` |
| `themes` | 是 | 题材标签数组，1~3 个。**由分类者按对这首诗的理解自行判断**选择最贴切的类目，不受固定清单限制。下列清单仅为命名风格参考（名词性、2~6 字、传统诗学术语感）：`山水田园` `边塞征戍` `咏物言志` `咏史怀古` `送别怀人` `羁旅思乡` `闺怨宫怨` `悼亡伤逝` `讽喻刺世` `爱国忧时` `干谒酬赠` `题画题壁` `闲适隐逸` `游仙梦幻` `哲理玄言` `节令风俗` 等；判断标准只有一个——类目是否准确概括这首诗的内容与主旨 |
| `body` | 是 | 诗词正文。每行用 `\n` 分隔，保留中文标点（，。？！；：），使用教材通行版本文字 |
| `translation` | 是 | 完整白话译文，书面语，准确通顺 |
| `notes` | 是 | 注释数组，2~6 条，每条形如 `{"w": "被解释的字词", "n": "释义"}`，选诗中真正需要解释的词 |
| `background` | 是 | **创作背景故事，150~300 字**。写清楚：诗人当时的年龄/处境/遭遇、时代背景与历史事件、写作缘由、相关典故或轶事。要求具体、生动、史实可靠；拿不准的细节宁可不写，严禁编造 |
| `famous` | 否 | 本篇真正的千古名句，0~2 条（每条是 body 中原句），无则省略字段 |
| `textbook` | 否 | 仅当该篇属于常见语文教材必背篇目时填写，取值：`小学必背` `初中必背` `高中必背` 之一 |

## poet 对象字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 是 | 姓名 |
| `dynasty` | 是 | 朝代，取值同上 |
| `years` | 是 | 生卒年，如 `701—762`；不确定写 `生卒年不详` |
| `honor` | 是 | 称号/雅号，如 `诗仙`；没有写空字符串 `""` |
| `bio` | 是 | 100~180 字小传：生平要点、创作风格、文学史地位 |

## 质量红线
1. **诗文文字必须准确**，以通行版本（人教版教材、《唐诗三百首》《宋词三百首》等通行选本）为准；若对某篇正文没有把握，宁可换成更有把握的名篇。
2. `background` 每篇不得少于 150 字，不得写成内容空洞的套话。
3. `id` 前缀必须使用任务指派的组号，不得与其他组重复。
4. JSON 字符串中的换行必须转义为 `\n`，引号转义为 `\"`。
5. 所有作品必须是公有领域古籍（清代及以前、或近代已故逾50年作者），不得收录在世或近代仍在版权期的作品。
6. 每写完一个文件用 Write 工具完整写出；内容再长也必须写完整，严禁用"略""等""…"截断任何字段。
